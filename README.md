# منصة الاختبارات الإلكترونية المؤمنة

منصة اختبارات إلكترونية عربية متكاملة للكليات: بوابة طلاب، بوابة أعضاء هيئة التدريس، ولوحة إدارة عامة، مع نظام مراقبة وحماية من الغش، وقاعدة بيانات مبنية على Google Sheets عبر Google Apps Script.

## بنية المشروع

```
├── index.html            # بوابة الطالب + لوحة الإدارة العامة
├── faculty.html          # بوابة عضو هيئة التدريس (إنشاء الاختبارات والمراقبة)
├── style.css             # التصميم المخصص (نهاري/ليلي)
├── js/
│   ├── config.js         # الإعدادات العامة (رابط الـ API والمتغيرات المشتركة)
│   ├── core.js           # الوضع الليلي، الأدوات المساعدة، طبقة الاتصال بالسيرفر
│   ├── student.js        # منطق الطالب: بدء الامتحان، الأسئلة، المؤقت، التسليم
│   ├── anticheat.js      # منظومة منع الغش وحماية نزاهة الامتحان
│   └── admin.js          # لوحة الإدارة العامة والتقارير والتصدير
├── google_apps_script.js # كود الـ Backend (يُنسخ إلى مشروع Google Apps Script)
└── .github/workflows/    # فحص تلقائي لسلامة الكود عند كل push
```

## الإعداد والتشغيل

### 1. قاعدة البيانات (Google Apps Script)

1. أنشئ Google Sheet جديداً.
2. من قائمة الإضافات افتح **Apps Script** والصق محتوى `google_apps_script.js`.
3. شغّل الدالة `setupDatabase()` مرة واحدة لتهيئة الجداول.
4. (موصى به) شغّل `setupDailyBackupTrigger()` مرة واحدة لتفعيل النسخ الاحتياطي اليومي.
5. من **Project Settings > Script Properties** أضف الخاصية `ADMIN_PASSWORD` بكلمة مرور قوية للمدير العام.
6. انشر المشروع: **Deploy > New deployment > Web app**، وحدد الوصول "Anyone".
7. انسخ رابط الـ Web app وضعه في `js/config.js` في المتغير `API_URL`.

> **مهم عند أي تعديل على كود الـ Backend:** يجب إنشاء نسخة نشر جديدة
> (Deploy > Manage deployments > Edit > New version) حتى تسري التحديثات.

### 2. الواجهة الأمامية

ارفع الملفات على أي استضافة ثابتة (Vercel أو GitHub Pages أو Netlify). لا تحتاج أي خطوة بناء.

## الأمان

- كلمات مرور الحسابات تُحفظ مشفرة (SHA-256 مع salt عشوائي لكل حساب)، وتُرقّى الحسابات القديمة تلقائياً عند أول دخول ناجح.
- قفل مؤقت 15 دقيقة بعد 5 محاولات دخول فاشلة لكل اسم مستخدم.
- جميع عمليات الإدارة وهيئة التدريس تتطلب توكن جلسة يصدره السيرفر عند تسجيل الدخول (صالح 6 ساعات).
- كل طالب يحصل على توكن جلسة امتحان خاص يُطلب عند التسليم، مع فرض مدة الامتحان من السيرفر.
- المكتبات الخارجية مثبتة بإصدارات محددة وهويات سلامة (SRI).
- منع الغش: حظر اختصارات أدوات المطور، كشف عادل متعدد القراءات، تعتيم الشاشة عند مغادرة النافذة، علامة مائية باسم الطالب، ومنع الدخول المكرر.

## النسخ الاحتياطي

- أي مسح للنتائج من لوحة الإدارة يؤرشف السجلات تلقائياً في شيت `ResultsBackup` قبل الحذف.
- النسخ الاحتياطي اليومي يعمل عبر المجدول `dailyResultsBackup` (انظر خطوة الإعداد 4).

## التحليلات والتقارير

- **بطاقات النظرة العامة (الإدارة):** ملخص فوري أعلى لوحة الإدارة: إجمالي التسليمات، عدد الامتحانات عليها نتائج، متوسط الدرجات، نسبة النجاح، تسليمات اليوم، وعدد حالات المخالفة.
- **تحليلات الامتحانات (الإدارة وهيئة التدريس):** تقرير لكل امتحان يعرض عدد التسليمات، المتوسط، أعلى وأقل درجة، نسبة النجاح، توزيع الدرجات، وتحليل صعوبة الأسئلة (نسبة من أجابوا صحيحاً على كل سؤال، مرتبة من الأصعب). الأستاذ يرى امتحاناته فقط.
- **فلتر المخالفات:** مربع "المخالفات فقط" بجوار بحث النتائج يعرض التسليمات المعلّمة بمخالفات مراقبة فقط، والتصدير إلى Excel يتبع الفلتر الحالي.
- **نسخ امتحان كقالب (هيئة التدريس):** زر "نسخ كقالب" بجوار أي امتحان يحمّل أسئلته في المحرر لتعديلها ونشرها كامتحان جديد بكود جديد.

> **ملاحظة تقنية:** تحليل صعوبة الأسئلة يعتمد على عمود جديد (العمود 11) في شيت `Results`
> يُسجّل تلقائياً مع التسليمات الجديدة. التسليمات القديمة تظهر في كل الإحصائيات
> الأخرى عدا تحليل الأسئلة. لا حاجة لأي تعديل يدوي في الشيت.
